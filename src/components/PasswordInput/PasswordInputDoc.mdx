### When to use

Use the PasswordInput component inside forms to securely collect sensitive information such as user passwords.

#### Password Input

Use a password input when collecting sensitive authentication data. For example:

- User login forms.
- Account registration.
- Password reset forms.
- Credential updates.

The input is masked by default (type="password") and can be temporarily revealed using the optional show/hide toggle.

---

#### Required Indicator

When the required prop is enabled, the label visually indicates that the field is mandatory.

- A “(Required)” label is displayed next to the field label.
- This helps users understand form completion requirements at a glance.

---

#### Show Password Toggle

The show password feature is optional and controlled via the showToggle prop.

- When enabled, a “Show password” / “Hide password” button appears.
- It toggles input visibility between masked and plain text.
- It does not affect form submission or validation.
- It improves usability for password entry without compromising default security.

---

### Accessibility

Password inputs must be clearly labelled and fully accessible to keyboard and screen reader users.

<div className="docsAccessibility">

#### Semantic usage

- Always use a `<label>` associated with the input via htmlFor and id
- Do not rely on placeholder text as a label replacement
- Use type="password" by default to ensure secure masking
- Wrap password inputs in a `<form>` when used for authentication flows
- Ensure toggle buttons are keyboard accessible (type="button" is required)

---

#### Label clarity

Labels should clearly describe the expected input. For example:

- Password
- Create password
- Confirm password

When required is enabled, the label visually indicates this state with a “(Required)” marker.

---

#### Show/Hide behaviour

When showToggle is enabled:

- The input type switches between "password" and "text"
- The toggle button updates its label dynamically (“Show password” / “Hide password”)
- The toggle does not submit the form
- The toggle must remain accessible via keyboard interaction

---

#### Error handling

When validation fails:

- Clearly indicate which password field is invalid
- Provide guidance for password requirements (if applicable)
- Avoid exposing sensitive authentication logic in error messages
