### When to use

Use the Input component inside forms to collect structured user data. Inputs should always be paired with a clear label and typically submitted via a form button.

#### Text Input

Use a text input when you need free-form text from the user. For example:

- Entering a name
- Providing a username
- Adding short single-line responses

---

#### Number Input

Use a number input when the value must be numeric. For example:

- Quantity fields
- Age input
- Simple numeric configuration values

Avoid using number inputs for values that may include formatting (e.g. phone numbers with spaces or + signs).

---

#### Required Input

Use a required input when a field must be completed before form submission. For example:

- Essential account details (e.g. name, email)
- Mandatory checkout information
- Required profile fields

---

#### Email Input

Use an email input when collecting email addresses. For example:

- Account registration
- Newsletter sign-ups
- Contact forms

---

#### Telephone Input

Use a telephone input when collecting phone numbers. For example:

- Account verification
- Delivery contact details
- Customer support forms

---

### Accessibility

Input fields must always be clearly labelled and associated with a form control. They should provide enough context for users to understand what data is expected and how to complete the field.

<div className="docsAccessibility">

#### Semantic usage

- Always use a `<label>` associated with an input via htmlFor and id.
- Do not rely on placeholder text as a replacement for labels.
- Group inputs within a `<form>` element when collecting user data.
- Use appropriate input types (email, tel, number) to improve usability and mobile experience.

---

#### Label clarity

Labels should clearly describe the expected input. For example:

- Email address
- Mobile number
- First name

---

#### Error handling

When validation fails:

- Clearly indicate which field has an error.
- Provide a helpful error message explaining how to fix it.
- Do not rely only on colour to communicate errors.

</div>
